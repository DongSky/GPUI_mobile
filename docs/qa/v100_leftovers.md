Highest-impact remaining gaps:

1. **Live JVM IME (`jstring`)** — host `jni_text_from_arg` uses UTF-8 `GetStringUTFChars` on Android; a live `ImeListener` on a device JVM still needs NDK + `jni-sys`.
2. **GPUI caret bounds** — `crates/gpui` has no `Window` IME-rect API. A real GPUI method needs a crate bump.
3. **Search-view morph** — AndroidX search morphs with a container transform. GPUI still has no `cx.transform`; contained expand uses height/margin/corner tokens only (no PathBuilder scale). Compact/docked is a layout swap, not a shared-element scale.
4. **`gpui::LineCap`** — `progress.rs` maps `StrokeCap::Round` to lyon until gpui re-exports `LineCap`.
5. **Nav rail `PopUp`** — OS `PopUp` on Linux/Android NativeActivity is still unproven; rail uses an inline GPUI overlay.
6. **Device APK** — no SDK/AVD/adb in this environment; `component_demo` still needs `cargo apk run` on a device/emulator.
7. **Live GPUI + Chrome recapture** — this VM cannot create a wgpu surface; Chrome `--screenshot` hangs (dump-dom works). Official-vs-catalog strips remain v19 left halves. Recapture HTML heroes (including TimePicker ClockFace margins + MonthsNavigation MonthYearHeight + DateRangePicker range-header chrome + DatePickerDialog DialogButtonsPadding + DateRangePickerTitlePadding / DateRangePickerHeadlinePadding + DatePickerModeTogglePadding + Date Input `InputTextFieldPadding` + empty headlines + SelectableDates + docked / range-hero / search / time heroes) when a display/screenshot pipeline works.
8. **Predictive-back** stays unimplemented. Modal rail predictive-back scale (`PredictiveBackMaxScaleXDistance` 24 / `Y` 48) needs `cx.transform` or an equivalent host scale. Nested Android `LazyColumn` overscroll glow is not in GPUI. Higher-res stills (current bundle is 128–240px) if official optical match needs print-size photos.

Do **not** reopen as missing: the v99 do-not-reopen list plus **TimePicker ClockDisplayBottomMargin / ClockFaceBottomMargin** (36 / 24 on Vertical, catalog `data-clock-face-margins`). Do not change shipped horizontal `HORIZONTAL_GAP_DP` 24 to official `ClockDisplayBottomMargin` 36.

## Suggested v101 order

1. Live IME / caret / search transform / `gpui::LineCap` if an NDK or gpui API bump becomes available (otherwise skip).
2. Highest remaining Visual QA gap that does not need a crate bump (OS `PopUp` and predictive-back scale stay skipped if still unproven / no `cx.transform`). Prefer recapture or a newly published Expressive spec delta. Official `DatePickerHorizontalPadding` 12 is already the `.cal` body inset; `YearsVerticalPadding` 16 is already `YEAR_GAP_DP`. YearPicker `requiredHeight` (`RecommendedSizeForAccessibility * (MaxCalendarRows + 1) - DividerDefaults.Thickness` = 335) still assumes 48dp calendar rows — do not apply it while day cells stay 40dp. `DisplaySeparatorWidth` 24 / `PeriodToggleMargin` 12 stay unused if still lower impact than recapture.
3. APK install + Chrome/wgpu recapture of v21–v100 heroes.
